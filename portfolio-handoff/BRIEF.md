## Technical notes for whoever picks this up

- `index.html` in this handoff is the current, Francis-approved version. It's a single self-contained file: all CSS and JS inline, fonts via Google Fonts `@import`, no build step, no framework.
- **Known debt to fix early:** the three images currently used (content screenshot, knowledge-check screenshot, branching-activity screenshot) are embedded directly in the HTML as base64 `data:` URIs. That was necessary for previewing in the cloud session this was built in, but it means Francis can't swap a photo without editing code. **First real task for this session: restructure so images live as separate files in an `images/` folder and are referenced with normal `<img src="images/filename.jpg">` paths.** The three real image files are included in this handoff's `images/` folder already, named to match what they show (`content-nonverbal-techniques.jpg`, `check-understanding-q1.jpg`, `branching-activity.jpg`) — wire those in properly instead of the baked-in base64 versions.
- Mobile breakpoints already exist (~860px and ~600px) and were checked — keep testing at those widths after changes.
- **Nav active-pill transition (two rounds of fixes on 2026-09-15, may still need a third):**
  1. First fix: the pill background moved off the link itself onto `.navlinks a::before` (a plain colored shape, no text), with *only that pseudo-element* carrying the shared `view-transition-name: nav-active-pill`, while the link text keeps its own separate permanent per-link name (`nav-link-profile`/`nav-link-portfolio`). **Don't put a shared view-transition-name back on the anchor itself** — an earlier (reverted) attempt did that, and it's what caused a glitch where the browser animates a *screenshot* of the named element, so the OLD page's label visibly slid into the NEW link's position for a frame before snapping to the correct text.
  2. This fixed the glitch but Francis reported the slide still mostly just snapped — worked occasionally, not consistently, no obvious trigger. Second fix: moved the Google Fonts / Fontshare loading from CSS `@import` (at the top of `styles.css`) to `<link rel="stylesheet">` tags in each page's `<head>`, plus `<link rel="preconnect">` hints. Reasoning: `@import` chains fetch serially (`styles.css` → the imported stylesheet → its font files) and are a documented suspect for cross-document view transitions being silently skipped if the destination page's styles/fonts haven't resolved by the time the browser checks its transition opt-in — which would explain "sometimes works, mostly doesn't" tied to font-fetch timing rather than anything deterministic in the code. Verified locally (6 rapid runs via a Playwright script, all showed a genuine mid-flight slide, no snaps) but **this is a plausible-cause fix, not a confirmed root-cause fix** — local testing can't reproduce real-world network variability. **If Francis reports it's still snapping after this, the next things to check are: (a) whether he's testing in a browser that supports cross-document View Transitions at all — Chrome/Edge 126+, not Firefox/Safari as of this writing; (b) whether he's clicking faster than the transition's ~0.3s duration, which legitimately aborts/skips a transition already in flight; (c) instrument with `pageswap`/`pagereveal` event listeners logging to the console to see whether `event.viewTransition` is even present on the failing navigations.**
- No React, no build tooling, no CMS/automation layer (folder-watching, auto-tagging, job-post analysis, etc.) has been built and **none of that should be assumed as a goal for day one.** Francis was inspired by a much more elaborate Reddit setup, but the guidance he was given was to get a working, editable static site first, and treat automation as a later, optional layer if he wants it at all — not a prerequisite.
- Recommend `git init` in the project folder (if not already done) before making changes, so everything is diffable/revertable — Francis is new to this and that safety net matters to him.
